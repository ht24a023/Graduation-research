# 卒業研究：記憶・承認・評価機能の利用と検証

対象：Documents/Codex/sotuken / 更新日：2026-11-06

## 研究として確認できること

ローカル優先の会話に、保存メモの検索と入力根拠の表示、通常会話でのクラウド承認制御、記録に基づくモード別評価を追加した。機能の実装、代替応答を使った操作検証、実モデルの応答検証は分けて扱う。

## 操作

1. サーバーを再起動し、ブラウザーを強制再読み込みする。古いブラウザー補助サービスが動いている場合は、そのプロセスも終了してから再起動する。
2. AI Core下の「記憶ネットワーク」で保存メモを追加・編集・削除する。
3. 保存メモと関係のある質問をする。記憶画面の「直近のモデル入力に含めた記憶」で、入力へ組み込んだメモを確認する。該当する点と一覧を緑色で表示する。
4. 上部の「研究レポート」で処理ログを集計する。モード選択、実験ID付き記録への絞り込み、集計JSON保存に対応する。

## 記憶の扱い

- 名前・好みなどの既存プロフィールに加え、質問に関連する保存メモを最大4件選択する。
- 英数字の語と日本語の連続2文字の共通部分を利用する。意味検索やニューラルネットワークの学習ではない。
- メモは1件につき最大1,400文字をモデル入力へ組み込む。長いものには「一部」と表示する。
- メモ変更後は、変更前の記憶を前提とした回答キャッシュを再利用しない。
- 緑色は入力に含めたことの表示。モデルが回答へ採用したことや、回答の正しさを保証しない。
- ネットワークの線は共通語による関連、流れる光は演出。モデルの内部思考や重みを可視化しているわけではない。
- 参照表示は直近の完了した処理についてのもので、ページ再読み込みをまたぐ永続的な利用履歴ではない。

## クラウド承認

通常会話の検索後に表示される承認ボタンを対象に、会話・承認対象・承認/拒否の種別を結び付ける。10分で期限切れとなり、どちらか一方を選ぶと同じ対象の反対側のボタンも無効になる。同時操作での二重利用を防ぎ、会話リセット時に保留中の承認と当該会話の回答キャッシュを破棄する。

LOCAL_ONLYでは、承認コマンドを受け取ってもクラウドを呼び出さない。FIXED_ROUTINGは比較実験用にクラウドを使う既存モードであり、通常会話の一回限り承認とは異なる。今回の検証では実クラウドを使用していない。

## 指標の定義

- 処理完了率：評価ログのsuccess=trueの割合。回答の正しさとは区別する。
- 応答時間：記録されたサーバー処理時間。中央値と、昇順のceil(n×0.95)番目によるP95を表示する。
- クラウド未使用率：api_calledが記録された要求のうち、クラウドLLMを使わなかった割合。検索や天気などの外部通信を含まない。
- 人手評価：good / partial / badを別々に数える。未評価は未評価として残す。
- 対応する実験ID数：3モードすべてに存在するtest_case_idの数。実験条件や品質の同等性まで保証する指標ではない。
- 費用・トークン：実課金・実トークン数の収集がないため、新しいレポートでは費用削減率を算出しない。既存画面の推定値とは分けて扱う。

レポートJSONは集計値のみ。入力文、回答文、評価コメント、記憶本文は含まない。実験ランナーのexperiment_result.jsonlには質問と回答が含まれるため、研究用のローカル記録として扱う。

## 比較実験

既存の60問セットを利用できる。実験ランナーは実行ごと・モードごと・繰り返しごとに会話を分離し、今回の実行の評価だけを集計する。途中の通信失敗も記録して後続を継続し、評価が欠けた件数を表示する。クラウド固定モードは明示的な指定が必要。

実行計画だけを確認する例（通信・モデル呼び出し・結果ファイル作成なし）：

```powershell
.\.venv\Scripts\python.exe run_experiment.py --dry-run --repetitions 3
```

ローカルのみで実験する例：

```powershell
.\.venv\Scripts\python.exe run_experiment.py --modes LOCAL_ONLY --repetitions 3
```

同じ質問セット・同じ順序・同じPC・同じモデル・同じ設定で比較し、初回モデル読み込みの有無、同時実行中のアプリ、ネットワーク、キャッシュの状態を記録する。少数の試行でP95や一般的な精度を断定しない。回答品質は各回答を確認して人手評価する。今回は60問の本実験を実行していない。

## 検証ファイル

- tests/test_research_completion.py：承認の別会話・別ボタン・期限・同時消費・LOCAL_ONLY、リセット、関連記憶、評価ログ同時更新、研究指標。
- tests/test_research_browser.py：実HTTP/Chromeによる研究画面、絞り込み、集計保存、スマホ幅、会話から記憶入力根拠への接続。応答と比較データは検証用の代替値。
- tests/test_experiment_runner.py：実行計画、クラウド固定モードの明示指定、実験分離、途中失敗、過去ログの混入防止。
- tests/test_neural_core.py：記憶の保存・再読み込み・検索・編集・削除。

実機ではOllamaのllama3を使い、検証用メモのコードを返す1件を確認した。実行条件と時間は進捗報告に記載する。一般的な日本語回答品質、実マイクの認識精度、長時間運転、外部アカウント・機器との接続は別途確認が必要。
