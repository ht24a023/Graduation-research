# iPhoneカレンダー・リマインダー連携

## UIで使える機能

サーバーを再起動して画面を再読み込みし、上部の **APPLE** を開きます。

- カレンダーの月表示・日付による絞込・予定一覧。
- リマインダー一覧、完了／未完了、保存先と件名・メモによる検索。
- 新規追加・編集・確認付き削除。終日予定、期限、優先度、場所、メモ。
- iCloudへの接続、ICS／JSONの事前確認付き取込、JSON／ICS書出。
- iPhone向けの変更ファイル作成と、実行結果の取込。

表示には反映状態を付けます。**「取込ファイル」「ファイル内で編集済み」はiPhoneへ反映された意味ではありません。** 「iPhone反映待ち」は、下記の変更JSONの適用と結果JSONの取込が必要です。

## 1. iCloudカレンダーに接続する

1. Apple Accountで2ファクタ認証を有効にし、[Appleの手順](https://support.apple.com/ja-jp/102654)でApp用パスワードを作成します。普段のApple Accountパスワードを入力しないでください。
2. PCで `http://localhost:8000/` を開き、APPLE →「接続・アップロード」を展開します。
3. Apple AccountのメールアドレスとApp用パスワードを入力して「iCloudに接続」。認証情報はサーバーのメモリーだけで保持し、ディスク・研究ログ・ブラウザー保存領域には保存しません。
4. カレンダーと期間を選び「iCloudから取得」。期間は366日以内です。
5. 保存先にそのiCloudカレンダーを選ぶと、追加・編集・削除はHTTPSのCalDAVでiCloudへ送信します。iPhoneでも同じiCloudカレンダーを有効にしてください。端末間の反映時間はiCloudの同期状況に従います。
6. 「接続解除」またはサーバー終了で認証情報を破棄します。取得済み予定はPCに残ります。

招待された会議・読取専用カレンダーは、このUIでは変更しません。繰り返し予定は月表示で展開します。編集・削除は確認したシリーズ全体を対象とし、繰り返し日時の変更・単独回の編集は対象外です。取得範囲外の月は別途取得してください。

iPhoneのカレンダーがGoogleやExchange等に保存されている場合、iCloudに接続してもその予定は取得できません。ICS取込など、実際の保存先に合った経路を選んでください。

## 2. ICS・JSONをアップロードする

1. カレンダーアプリ等から書き出した `.ics`、このUIのJSON、または下記のiPhoneスクリプトが作ったJSONをPCへ用意します。
2. APPLE →「接続・アップロード」でファイルを選択します。1.5MB以内です。時差が指定されていないICSは指定タイムゾーンで解釈します（初期値Asia/Tokyo）。
3. 件数・先頭の件名を確認してから「確認した内容を取り込む」を押します。選択だけでは保存しません。
4. 同じ名前のICS／汎用JSONはUIDを使って重複を防ぎます。UIで編集済みのファイルへの再取込は拒否し、別名での比較を求めます。異なる名前のファイルは別の保存先として扱います。
5. ファイル内での編集結果はJSON／ICSに保存できます。ICS内のVTODOはUIでリマインダーとして扱いますが、iPhone標準アプリへのVTODO取込・自動反映を保証するものではありません。

PC内の新規予定・リマインダーも作成できます。その保存先は「PC内…（iPhone未反映）」と表示します。

## 3. iPhoneのリマインダーを取り込み、変更を戻す

iCloudカレンダーのCalDAV接続で、新しいAppleリマインダーまで同期できるとは扱っていません。リマインダーはiPhone上の[Scriptable](https://scriptable.app/)から標準リマインダーAPIを使う補助スクリプトで受け渡します。補助アプリは利用者自身でインストールし、リマインダーへのアクセスを許可する必要があります。

### 初回の取込

1. APPLEの「iPhone用スクリプトを保存」で `AI-Reminders-Sync.js` を保存します。このフォルダにも同じファイルがあります。
2. ファイルをiCloud Drive等でiPhoneへ移し、Scriptableで新しいスクリプトとしてコードを登録します。
3. Scriptableで実行し「PCへ送るJSONを作る」を選び、送るリマインダーのリストを選択します。
4. 作成したJSONを「ファイル」へ保存し、PCへ移してAPPLE画面から取り込みます。

### UIからの追加・編集・削除をiPhoneへ反映

1. UIでiPhone由来のリストを保存先に選び、追加・編集・削除・完了を操作します。変更はまず「iPhone反映待ち」になります。
2. 「iPhoneに渡す変更JSON」で `AI-iPhone-changes.json` を保存し、iPhoneへ移します。
3. Scriptableを実行して「PCの変更JSONを適用」を選びます。対象のリストと変更JSONを選び、追加・編集・削除の一覧を確認して適用します。適用後は標準リマインダーアプリに保存されます。
4. 出力された結果JSONをPCへ戻し、APPLEから取り込みます。成功は「反映済み」、失敗は理由を表示します。

**ファイルの受け渡しは手動です。常時自動同期ではありません。** スクリプトにはHTTP通信・ログイン・連携トークンは含めていません。ネットワーク向けの予定APIは増設していません。ファイルに個人の予定が含まれるため、利用者が選んだ保存先で管理してください。

スクリプトはiPhoneの変更前の内容と比較し、別の変更を検出すると上書きを止めます。操作IDとiPhone内の実行記録で同じファイルによる二重追加を防ぎます。中断時に結果が不明なら、自動で再実行せず本体の確認を求めます。取り消した古い変更JSONを後から実行しないでください。

読み取れるのはScriptable/iOSが返す範囲で、APIには取得期間の制限があります。最大3000件、ファイルサイズはPC側の1.5MB制限に従います。大きい場合はリスト単位で分けてください。繰り返し・サブタスク・位置通知・添付・共有設定などの高度な属性は編集画面で管理しません。既存リマインダーの更新時には繰り返しルールを削除しませんが、繰り返しの完了・削除では系列に影響する可能性があるため、iPhone側でも確認します。

## 保存先と安全な更新

PC側のデータは `data/apple_agenda.json` に保存します。既存のMISSIONとは別の保存先です。アカウント情報・画像・予定をLLMへ送る処理はありません。iCloudの更新・削除はETagによる条件付き送信を行い、競合時に拒否します。追加も同じ要求IDを再利用し、二重追加を防ぎます。

APPLEの個人情報APIはバックエンドPC内の同一オリジンだけで操作できます。スマートフォンからLANのIPで直接この個人情報UIを使う構成ではありません。

## 検証状況

ICSの解析・再出力、終日・繰り返し、UID重複防止、追加・編集・削除、競合防止、iPhone変更キューと結果取込、実HTTP/ChromeのUI操作を検証しています。iPhoneスクリプトはScriptable APIの代替環境で追加・編集・削除・二重追加防止・競合・結果出力を検証しています。

**実際のApple Accountへのログイン、iPhoneの権限許可・実リマインダーへの書込は未確認です。** アカウントとiPhoneの初回設定後に実機確認が必要です。実装テストの成功を実アカウントの同期成功とは扱っていません。
