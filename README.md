# sotuken：ローカル優先AIアシスタント

## 起動

Windows PowerShellで、このフォルダに移動して実行します。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe local_ai_server.py
```

ブラウザーで http://localhost:8000/ を開きます。変更前から起動している場合はサーバーを再起動し、ブラウザーを強制再読み込みしてください。

ローカルLLMにはOllamaと `config.py` の指定モデルが必要です。クラウド利用には `.env` のAPIキーを設定します。キーなしでも画面・専用ツール・ローカル機能は起動できます。

## 画面と情報パネル

中央チャットの位置と画面下の入力欄は固定し、会話履歴だけがスクロールします。左右に必要なパネルを開けます。複数のパネルや長文がある場合は、パネル内だけをスクロールします。

天気、地図、現在地、翻訳、文書、システム情報、Web検索・Wikipedia、YouTube、処理履歴、性能、QRコードに対応しています。

- 上部のボタンで手動開閉します。パネルの「⇄」で左右を変更できます。
- 実行したツールの戻り値にカード種別を付け、SSEで自動表示します。AIの回答文からカード内容を推測しません。
- 自動切替で閉じるのは、自動表示され、手動操作・ピン留めされていないパネルだけです。手動で開いたパネルは維持します。
- 「×」で対象だけ閉じ、「すべて閉じる」でピンも含めて収納します。処理中に閉じたパネルは、その処理の完了通知では再び開きません。
- 「自動表示」をオフにすると、手動で選択したパネルだけ表示します。
- 翻訳では原文、結果、言語の選択、外部翻訳画面へのリンクを表示します。取得に失敗した場合はエラーを表示し、結果を補いません。
- 文書パネルには既存の文書一覧・閲覧・編集機能を接続しています。文書IDに続けて「を表示して」と入力できます。
- YouTubeは取得できた動画のタイトル・サムネイル・視聴リンクを表示します。アクセス制限時は取得失敗と検索リンクを表示します。
- QRコードは `qrcode` を使ってPC内で生成し、SVGで保存できます。QRの文字列を外部QRサービスに送りません。

例：`大阪の天気を教えて` / `こんにちはを英語に翻訳して` / `CPUの使用率を教えて` / `https://example.comをQRコードにして`

## AIコアとシステムモニター

AIコアは待機、音声検出、音声認識、意図判定、ツール実行、ローカル推論、クラウド推論、回答、エラーを実際のイベントに連動して表示します。同心円、分割リング、傾斜リング、目盛り、走査線、粒子は固定した少数のDOM要素を使います。非表示タブではコアのアニメーションを止め、動きを減らすOS設定にも従います。

システム情報はブラウザーを開いた端末ではなく、Pythonを実行中のPCの値です。約2.5秒ごとに更新します。通信速度は差分が必要なため初回は「計測中」です。ディスクはアプリのあるドライブ、通信量はPC全体です。

CPU温度はOSの対応センサーのみ、GPUは `nvidia-smi` が利用できるNVIDIA機のみ対応（15秒ごと採取）。非対応・未取得の値は推測しません。端末位置はユーザーの許可が必要です。IP推定の誤差は不明、手動位置は地域の代表地点として区別します。

## 計測と研究用の記録

- サーバー：`perf_counter()` で意図判定、各ツール、ローカルAI、クラウドAIを分けて計測します。ツール内部で使うLLMも接続層で計測します。集計・CSVには内包する別処理を除いた固有時間を使い、二重計上を防ぎます。個別ステージの履歴には実際の開始〜完了時間も残します。
- ブラウザー：送信からの経過時間を100ms間隔で更新し、初回テキスト表示、テキスト表示完了、音声出力完了を区別します。
- 音声認識：音声入力操作から認識結果の確定まで。発話時間を含み、認識エンジン内部だけの時間ではありません。手入力し直した場合はその認識時間を送信データに付けません。
- 音声合成：ブラウザーは内部の生成時間を公開しないため「計測不可」と扱います。合成依頼から発話開始までの待ち時間、実際の再生時間、送信から発話完了までを別々に記録します。
- 現在の通常応答は一括テキストです。サーバーのテキスト生成完了と、ブラウザーの初回表示時刻を区別します。生成中の最初のトークン時刻は未計測（空欄）です。
- サーバー時計とブラウザー時計を直接引き算しません。計測方法の異なる値を同じ時間として扱いません。

各会話の折りたたみ表示、「処理履歴」「性能」から結果を確認できます。`data/processing_log.jsonl` にリクエストIDとセッションIDを付けて保存し、性能パネルから詳細CSVを保存できます。CSVは直近100件までです。未実行・計測不可は空欄で、0秒と区別します。`PROCESSING_LOG_PATH` 環境変数でログ先を変更できます。

## 音声

対応ブラウザーのSpeechRecognitionとマイクAPIを使用します。HTTPSまたはlocalhostが必要です。ブラウザー提供元へ音声が送信される場合があることを画面に明記しています。認識結果は入力欄に入れ、送信は手動です。検出中のリングは実マイク音量で脈動します。

読み上げは初期状態でオフです。ブラウザー音声合成の開始・終了イベントに合わせて発光します。出力波形は公開されないため、回答中の光は音量の実測ではありません。

## 外部サービスとテスト

外部検索・天気・翻訳・動画情報は、各サービスの制限や障害の影響を受けます。取得失敗をデモデータや推測値で成功に置き換えません。翻訳の別プロバイダーへの自動転送は実装していません。

天気APIの仕様確認：[Open-Meteo公式ドキュメント](https://open-meteo.com/en/docs)。`current` の `time` は出力に含まれる時刻であり、取得変数として指定しません。

開発用ライブラリは `requirements-dev.txt`、主な新規テストは `tests/test_workbench.py` と `tests/test_workbench_browser.py` です。ブラウザーテストは `e2e` マーカーを付け、Chromeを使用します。既存の `test_search_fix*.py` は実サービスを呼ぶ検証スクリプトなので、オフライン単体テストとは分けて実行してください。
